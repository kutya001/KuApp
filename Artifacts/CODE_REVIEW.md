# Код-ревью KuApp — 17.10.2026

Обзор платформы (`index.html`, `gas/Code.gs`, `sw.js`) и мини-игр (`apps/*.html`).
Находки отсортированы по серьёзности. В этом же проходе добавлен сетевой режим
(см. раздел «Что исправлено в этом проходе»), остальные пункты — задел на следующие итерации.

Серьёзность: **critical** — безопасность/потеря данных, **high** — функция не работает,
**medium** — заметный дефект, **low** — косметика.

---

## 1. Платформа и бэкенд

### 1.1 [critical] Бэкенд GAS без авторизации
`gas/Code.gs` (doPost), `gas/appsscript.json` (`access: ANYONE_ANONYMOUS`, `executeAs: USER_DEPLOYING`).
URL веб-приложения захардкожен в `index.html` (HARDCODED_GAS_URL) и виден всем. Любой может POST-ом вызвать
`deleteSheet`, `deleteRows {startIndex:0,endIndex:100000}`, `update sys_Users!D2 = admin`, прочитать `sys_Users`.
Проверка роли есть только в UI.
**Исправление:** в `doPost` требовать токен сессии (Script Property + выдача после логина), проверять роль
admin на сервере для `deleteSheet/deleteRows/addSheets` и для записи в `sys_*`.

### 1.2 [critical] Пароли в открытом виде, таблица пользователей целиком уходит на клиент
`index.html` — `loginUser` читает `sys_Users!A2:G5000` и сравнивает пароль строкой; `registerUser` пишет пароль как есть;
`loadAdminUsers` тоже получает колонку Password. `PlatformAPI.db.read` валидирует только имя листа, поэтому любое
приложение в iframe (или гость из DevTools) делает `PlatformAPI.db.read('sys_Users!A2:G5000')` и получает все пароли.
Роль хранится в localStorage (`mcg_user`) и редактируется во вкладке «Настройки → Кэш» → `role:"admin"`.
**Исправление:** login/register перенести в GAS (`action: 'login'`), хранить хэш (SHA-256 + соль через
`Utilities.computeDigest`), клиенту отдавать только `{login, role, token}`; запретить `sys_` в `validateSheetRange`.

### 1.3 [high] Инъекция формул в Google Sheets
`gas/Code.gs` — `doAppend/doUpdate/doBatchValues` пишут через `setValues`, строки, начинающиеся с `=`, выполняются как формулы.
Гость вызывает `PlatformAPI.system.log('x','e','=IMPORTXML(...)')` и формула выполняется в таблице владельца.
**Исправление:** `range.setNumberFormat('@')` перед `setValues` либо экранирование `= + - @` апострофом.
Заодно закрывает п. 1.7.

### 1.4 [high] Stored XSS: `esc()` не экранирует кавычки
`index.html` — `esc` экранирует только `& < >`, а значения подставляются в атрибуты и inline-обработчики
(`title="${esc(val)}"`, `ondblclick="editDataCell(...,'${esc(val)}')"`, `data-app="${esc(r.app)}"`,
`onclick="openDataSheet('${esc(name)}')"`). Гость логирует строку с `" onmouseover="…` → вкладка «Статистика»
(доступна всем) выполняет JS.
**Исправление:** добавить в `esc` замену `"`→`&quot;`, `'`→`&#39;`; в обработчики передавать индексы, не значения.

### 1.5 [high] Service Worker: Cache First навсегда для `apps/*.html` и `apps/index.json`
`sw.js` — всё same-origin кэшируется при первом запросе и больше не перезапрашивается, пока не сменится `CACHE_NAME`.
README обещает Network First для приложений — это не так. Обновили игру без правки `sw.js` → пользователи
видят старую версию бесконечно. В `externalHosts` нет `ipapi.co`, `api.ipify.org`.
**Исправление:** для `/apps/` и `*.json` — Network First с fallback в кэш (или stale-while-revalidate).
*В этом проходе кэш поднят до `app-v8`, чтобы доехали сетевые игры.*

### 1.6 [medium] Гонки без LockService и адресация строк по позиции
`gas/Code.gs` — `doAppend` берёт `getLastRow()+1` без блокировки: два одновременных `append` пишут в одну строку.
`index.html` `submitScore` — read-modify-write TotalXP без блокировки, строка ищется по индексу, который мог
сдвинуться после `deleteRows`. То же в `adminToggleRole/Block`.
**Исправление:** `LockService.getScriptLock().waitLock(10000)` в `doAppend/doUpdate`; серверное действие
`updateUserXP`, ищущее строку по логину.

### 1.7 [medium] Автоконвертация типов при записи ломает логин
`setValues` превращает `"0123"` в `123`, `"12.05"` в дату, `"TRUE"` в boolean. Пароль `0077` → «Неверный логин или пароль».
**Исправление:** `setNumberFormat('@')` перед записью (см. 1.3).

### 1.8 [medium] Утечка IP и геолокации гостей
`index.html` `getGuestIdentity` запрашивает ipapi.co и пишет `Гость (IP · Город, Страна)` в `sys_Logs`;
вкладка «Статистика» доступна всем гостям.
**Исправление:** случайный `guest_<id>` в localStorage; IP логировать только на сервере при необходимости.

### 1.9 [medium] `openDataSheet` читает `A1:ZZ5000`, бэкенд не ограничивает ширину
`gas/Code.gs doRead` обрезает строки по `getLastRow()`, но колонки берёт из запроса (ZZ = 702).
Лист в 2000 строк → 1.4 млн ячеек → таймаут GAS.
**Исправление:** `numCols = Math.min(ref.getNumColumns(), sh.getLastColumn() - col + 1)`.

### 1.10 [medium] SW устанавливается при неудачном `addAll`, offline-fallback падает
`sw.js` — `.catch(console.warn)` глотает ошибку установки; при офлайне `caches.match('./index.html')` может
вернуть `undefined` → `respondWith(undefined)` → TypeError.
**Исправление:** убрать catch; `caches.match(...).then(r => r || new Response('Offline', {status:503}))`.

### 1.11 [low] Мёртвая ветка настройки подключения
`loadCfg()` всегда перезаписывает `cfg.gasUrl` хардкодом, поэтому экран setup и «Изменить подключение» бесполезны.

### 1.12 [low] `closeAllModals` не определена
Escape вне iframe → `ReferenceError`.

### 1.13 [low] `sandbox="allow-scripts allow-same-origin"` не изолирует приложения
Такая комбинация равна отсутствию sandbox для same-origin. Плитка «GAS WebApp» открывает `doGet`, который
возвращает JSON и запрещает фрейминг — бесполезна.

### 1.14 [low] `gasCall` не умеет не-JSON ответы и не имеет таймаута
При превышении квоты GAS отдаёт HTML со статусом 200 → «Unexpected token <».

### 1.15 [low] `submitScore` рапортует об успехе при неудаче
Ошибки записи глотаются, затем показывается «🏆 Очки сохранены».

Дополнительно: `apps/dictionary.html` вызывает `Platform.db.batchStructural`, которого в PlatformAPI нет.

## 2. Игры

## 5. Ревью игр и единый стиль — 22.10.2026

Все 20 игр прочитаны целиком, найденные баги исправлены, оформление переведено на общий стиль
«Неоновая аркада» (эталон — Тетрис): `apps/ku-arcade.css` + `apps/ku-arcade.js`, шрифты Russo One и Rubik
лежат локально в `apps/fonts/`. Каждая игра проверена в браузере внутри макета платформы (кнопка «←» поверх
iframe): телефон 390×844 и 360×640, десктоп 1280×800, сценарий «меню → игра → пауза → конец → снова/в меню»,
ошибок в консоли — 0.

### 5.1 Общее (платформа и все игры)
- **[medium] `confirm()`/`alert()` и скачивание файлов не работали внутри платформы.** У iframe не было
  `allow-modals` и `allow-downloads`: `confirm()` молча возвращал `false`, поэтому не срабатывали все «Сбросить?/Удалить?»
  (Тетрис, Сапёр, 2048, а также Тренер, Словарь, Конструктор, Маркетплейс), экспорт JSON блокировался.
  → В `index.html` добавлены `allow-modals allow-downloads`; в играх — диалог в стиле набора `KuArcade.confirm()`.
- **[medium] Кнопка «←» платформы перекрывает левый верхний угол игры (≈64×64 px).** У части игр там стояли пауза/меню
  (Wall Rush, Тетрис, Мемори, Судоку, 2048…) — нажатие выкидывало из игры. → Шапка `.ku-top` резервирует место,
  кнопки игр — только справа.
- **[medium] Физика привязана к частоте кадров** (на 120/144 Гц игры шли в 2–2,4× быстрее): Pong, Flappy, Dino,
  Pac-Man, Арканоид, Баскетбол, Бильярд, Змейка. → Фиксированный шаг с накопителем времени, константы прежние.
- **[medium] Зависимость от CDN.** 2048 и Бильярд держались на Tailwind с CDN — офлайн (PWA) вёрстка рассыпалась;
  у Тетриса и Сапёра шрифты грузились только кириллицей — латиница шла системным шрифтом. → Всё локально.
- `sw.js`: кэш `app-v13` (новые `ku-arcade.*`, шрифты, игры).

## 6. Русский бильярд: реалистичная физика и графика — 22.10.2026

Скрипт `apps/billiard.html` переписан целиком (разметка, стиль и режимы прежние).

**Физика** (шаг 1/1200 с, только + − × ÷ √ — удар по сети проигрывается у соперника бит-в-бит):
- шар — твёрдое тело: скорость и вектор угловой скорости; на сукне точное решение «скольжение (μ = 0,2) →
  качение (μ = 0,011)», вращение вокруг вертикали гаснет отдельно. Отсюда накат, оттяжка, стоп-удар;
- шар–шар: восстановление 0,95 и трение в контакте (μ = 0,06) — отброс прицельного 0,7–3,3° при резке
  и ±2,4° от бокового винта; момент касания уточняется внутри шага (откат по скоростям);
- борт: нос резины на 64 % диаметра, упругость 0,83 → 0,6 с силой удара, трение 0,17 — винт по ходу
  удлиняет угол отскока и ускоряет шар, против хода — укорачивает;
- лузы по стандарту (угловые 73 мм, средние 83 мм), губки — капсулы с радиусом 7 мм, стенки расходятся
  на 8°/14°; шар падает, когда центр ушёл на 2 мм за линию створа. Окно попадания по оси: угловая ±4–6 мм,
  средняя ±12–14 мм; угловая принимает шар до ~30° к оси, средняя — до ~45°; тихий шар заходит легче.

**Прицел** считается той же физикой: направление прицельного совпадает с реальным в пределах 0,01°
(400 случайных ударов); «зелёная» линия — 47 предсказанных попаданий из 50 реальных, ложных — 0
(учтены скорость — шар может не докатиться — и дребезг в губках).

**Графика:** статичный стол рисуется один раз в буфер (брус «на ус» с волокнами, перламутровые метки,
кожаные лузы с латунью и сеткой, сукно с фактурой, свет трёх ламп, тени от носа резины); шары — попиксельно
освещённые спрайты, блики и мягкие тени от каждой лампы с учётом расстояния; номера катятся вместе с шаром
(кватернион); кий — спрайт с наклейкой, кольцом, «пиками» и обмоткой, отходит при натяжении силы, бьёт и
проводит удар; шар проваливается в лузу. Цвета сукна — реалистичные (старые неоновые сбрасываются на зелёное).

**Управление:** микро-прицел с ускорением (медленно — 0,00008 рад/px, быстро — до 0,002), ← → — 0,0002 рад
(с Shift — 0,01): лузы всего на 5 мм шире шара, прежней точности (0,002 рад/px) не хватало.

**Сеть:** если соперник вышел, пока катились шары (его удар или мой), ход не засчитывается и окно
«Соперник вышел» больше не подменяется окном фола — раньше после него стол оставался «мёртвым».
Удар шлётся в новом формате (скорость + вектор вращения) с полями старого формата — клиент со старым
кэшем не падает, а проигрывает удар своей физикой и встаёт по снимку.

**Мобильный вид** (короткая сторона экрана ≤ 560 px): стол почти на весь экран — 79 % площади на 390×844
и 430×932 (было ~50 %), 73 % на 844×390. На экране только управление, счёт одной строкой и кнопка ☰;
панели игроков, сукно, настройки стола, правила и действия — в одном меню партии (оно же пауза, на всех
экранах). В портрете сила — горизонтальная шкала под столом, в альбомной — вертикальная слева; тап по шкале
без протяжки удар не делает. Чей ход — ещё и по цвету свечения рамки стола. Проверено на 360×640, 390×844,
430×932, 640×360, 844×390 (внутри платформы, без перекрытия кнопки «←»), поворот экрана во время партии,
планшет и компьютер — прежняя раскладка. `sw.js` → `app-v15`.

**Проверено:** разбой (40 вариантов) — перекрытий и вылетов за стол нет; детерминизм — повтор удара даёт
те же координаты; сеть — два клиента на эмуляторе комнат, конец проигрывания совпадает с ударившим до 0,01 мм
(округление снимка), реванш и выход соперника работают; локальный сценарий (фол-промах, забил — бьёт ещё,
биток в лузу — фол и возврат на заднюю отметку, победа после остановки шаров, пауза, настройки);
ошибок в консоли — 0. Кадр ~3–4 мс (холст 2000×1090), прицел ~0,1 мс. `sw.js` → `app-v14`.

## 7. Русский бильярд: 3D-вид, наклон кия, точный винт, сила в %, полная траектория — 22.10.2026

**Наклон кия** 0–75°: удар раскладывается на скорость вдоль стола (× cos угла) и вращение вокруг оси,
перпендикулярной кию (`applyCue`). С боковым винтом шар уходит по дуге в сторону винта — итоговый угол
ухода ≈ atan(0,4·tg θ) при 80 % бокового (15° → ~6°, 45° → ~22°, 75° → ~57°); с оттяжкой ход гаснет
быстрее (75° + оттяжка 50 % — вперёд 8 см, вбок 0,9 м). При 0° формулы совпадают с прежними —
физические тесты (накат/оттяжка/стоп, отброс, борт, разбой, детерминизм) дают те же числа.

**Винт:** протяжка по маленькому шару — быстрая настройка, тап — окно точной настройки: большой шар,
стрелки с шагом 1 % (с автоповтором), проценты наката/оттяжки и бокового, наклон кия (ползунок и ±1°)
со схемой. На маленьком шаре — значок угла наклона.

**Сила** в процентах с шагом 1 % (шкала, − / +, ↑ ↓, с Shift — 5 %): на экране ровно та сила, с которой будет удар. Режим «Бить кнопкой «Ударить»»
(по умолчанию, настройка «Удар»): сила остаётся после отпускания шкалы и после удара — можно поправить
прицел и бить кнопкой «Ударить» (пробел / Enter); выключен — прежнее поведение (удар при отпускании).

**Полная траектория** (`simulateShot`): копия стола считается тем же шагом физики `physStep`, что и игра
(общее ядро с обработчиками событий: соударение, борт, луза), поэтому прогноз совпадает с ударом бит-в-бит:
10 случайных расстановок по 16 шаров со случайными силой, винтом и наклоном — расхождение 0 мм,
несовпадений по лузам 0. Поколения: биток — 0, шары, которые он ударит, — 1, и т. д.; глубина 1–5 / «Все».
Разбой (16 шаров, 7,25 с игры) считается ~35 мс на компьютере, на медленном телефоне — в разы дольше, поэтому
расчёт идёт кусками не больше ~6 мс за кадр; пока новый прогноз не готов, виден прежний (бледнее) — если он
для того же битка и той же расстановки. Ключ прогноза — точные значения прицела, силы, винта и наклона.

**3D-вид** (WebGL 1, без библиотек, ~670 строк): текстура стола из 2D-слоя (2048×1024, мип-уровни,
анизотропия), объёмные рама, резина с наклонным верхом, царга, шесть ножек, паркет со светом ламп и тенью
стола; шары — сферы с освещением трёх ламп и номерами на касательной плоскости (катятся вместе с шаром),
мягкие тени; кий — конус с наклоном и смещением к точке удара. Камера за битком: точка взгляда
подбирается так, чтобы дальний борт стоял у верхнего края кадра, а биток — в нижней половине; обзор
подбирает дальность, чтобы весь стол вошёл в кадр и стоял по центру. Ввод: протяжка — прицел и высота
камеры, щипок / колесо — приближение, тап по шару — биток (луч из камеры), по сукну — прицел.
Линии прицела и полной траектории рисуются поверх с проекцией и отсечением за камерой.
Потеря контекста WebGL (`WEBGL_lose_context`) — после восстановления всё создаётся заново.

**Независимая проверка кода** нашла и исправлено: тап в 3D выбирал ближний к камере шар, а не тот, в который
попал луч (теперь — первое пересечение луча со сферой); после щипка оставшийся палец «дёргал» прицел (до 57°);
на силе 1–2 % прогноз показывал удар в 40 % (порог прогноза = порог удара; при ударе отпусканием шкалы первые
2 % — по-прежнему отмена); ключ кэша прогноза округлял силу и угол — мог остаться прогноз соседнего удара;
полный расчёт разбоя на телефоне подвешивал прицел (теперь — кусками); 3D, включённое при потерянном контексте
WebGL, оставалось пустым после восстановления; окно винта и наклона открывается с клавиатуры (Enter / пробел
на шаре винта, стрелки ±1 %, Shift — 5 %, Home — центр, Esc — закрыть, фокус возвращается).

**Сеть:** в удар добавлены наклон и сила (для анимации кия у соперника); физика переносится скоростью
и вектором вращения, как раньше. Проверено: удары массе 40°/55°/20° с винтом — у соперника (в 3D)
расхождение 0,0 мм после снимка, конец проигрывания — 0,009 мм.

**Настройки** — версия 2 (`billiard_prefs`): сукно, режим удара, траектория и глубина, вид 2D/3D,
номера; старые (`traj: true/false`) переносятся. Сегменты в меню партии больше не вылезают за край окна.

**Проверено:** 360×640, 390×844, 844×390, 1280×800 — 2D и 3D, окно винта помещается без прокрутки
(в альбомной — схема наклона рядом с ползунком), меню, полная траектория; сценарии: кнопка «Ударить»,
чекбокс выключен, тап по шкале (в режиме кнопки — только выставляет силу), клавиатура, винт, пауза,
поворот экрана, сеть (разбой, ходы, победа, реванш, выход соперника); ошибок в консоли — 0.
`sw.js` → `app-v16`.

## 8. Судоку: новая игра — 22.10.2026

Прежняя «Судоку PRO» (одна версия 9×9, синхронная генерация с фризом UI — см. замечание в разделе 2) заменена
на месте (`apps/sudoku.html`, id `sudoku` прежний — очки и место в каталоге сохраняются).

**Устройство.** Движок — одна функция-фабрика `SudokuEngine()` без внешних зависимостей: та же функция работает в
основном потоке и в фоновом Web Worker (поток собирается из `SudokuEngine.toString()` в Blob; если поток недоступен —
генерация идёт кусками по 14 мс). Генерация по зерну (mulberry32): судоку дня (`hash('daily-v1-' + дата)`) и уровни
кампании одинаковы на всех устройствах. Перебор для единственности — клетка с наименьшим числом вариантов, скрытые
одиночки, для киллера — допустимые суммы и комбинации; логический решатель — те же приёмы, что видит человек.

**Сложность — по приёмам.** Генератор убирает цифры, пока решение единственно, затем оценивает головоломку решателем:
слишком сложно — открывает цифры там, где логика встала (а если это слишком упрощает — наугад), не проскакивая нижнюю
границу уровня; слишком много открытых цифр для уровня (больше 33 на сложном и эксперте) — ищет другую.
Киллер: те же шаги плюс комбинации сумм, обязательная цифра суммы, правило 45 для строки, столбца, блока и полос
из 2–3 строк (столбцов): «торчащие» клетки внутри одной области считаются как виртуальная клетка-сумма.
Найденное при проверке и исправлено:
- уровень киллера раньше не проверялся решателем (ставился по размеру клеток-сумм), и на сложном и эксперте логика
  вставала в 4 головоломках из 6 — подсказке приходилось «открывать клетку» (5–7 раз за партию). Теперь решатель
  проходит любую головоломку до конца: 3 226 подсказок подряд в киллере — ни одного «открытия»;
- проверка единственности киллера шла с пустых кандидатов и упиралась в предел перебора; теперь перебор начинается
  с того, что уже вывела логика (её выводы верны для любого решения), — эксперт киллера: 1,1 с → 0,15 с (медиана);
- у диагонали и гипера «сложные» выходили с 41–47 открытыми цифрами — теперь 18–33.

**Проверено (движок, Node):** все версии × сложности по 10 зёрен: решение единственно (независимым перебором),
уровень совпадает с заданным, решатель проходит до конца, ни один шаг логики не противоречит решению,
генерация детерминирована. Подсказки из середины партии — 432 проверки, 0 неверных. Время генерации (среднее /
максимум): классика 15–180 мс / 0,55 с, пазл-эксперт 0,35 / 1,5 с, киллер-эксперт 0,2 / 0,9 с; в браузере
(поток) — до 1 с.

**Интерфейс.** Подсказка — следующий шаг с объяснением и подсветкой области и клеток приёма (с исключениями, без
которых шаг не увидеть: «N шагов, ниже — последние»). На маленьком экране панель подсказки поднимается над полем,
но не закрывает нужную клетку (иначе встаёт сверху). Тосты в игре — в зазор между HUD и полем (не закрывают счёт
дуэли). Выбор версии — три в ряд и на телефоне: сложность и описание видны без прокрутки; сегменты настроек
не вылезают за край окна (ширина набора 340 px > ширины окна на 360–390 px).

## 9. «Мячик»: новая игра — 23.10.2026

## 12. Бильярд с руки и московская пирамида, стены Wall Rush, Bounce Classic — 23.10.2026

### 12.1 Русский бильярд: биток с руки, правила, «Московская пирамида»

- **Источники правил:** правила Международной конфедерации пирамиды (свободная пирамида и общие правила) и Лиги
  любителей бильярда (комбинированная пирамида и общие правила пирамидных игр).
- **Биток с руки:** установка в доме перетаскиванием или тапом (2D и 3D, мышь, касания, стрелки), дом подсвечен, на
  линию дома / вплотную к шару / в борт шар не встаёт (ближайшая допустимая точка и подсказка); «Готово» — к прицелу,
  «Переставить» — обратно; в 3D при установке протяжка двигает шар, а не камеру. Механика общая: зоны «дом / временный
  дом / весь стол» и правило «первым — шар вне зоны».
- **Свободная пирамида по правилам:** разбой только жёлтым с руки; правильный разбой (забит шар, или 3 разных шара у
  бортов, или 2 у бортов и шар за средней линией) — по событиям физики; после неправильного разбоя — штрафной шар и
  выбор соперника из четырёх вариантов (бить / передать / перестановка и разбой сам / нарушитель); фол — соперник
  снимает любой шар себе на полку (штрафной), затем «бить самому / передать удар»; правильно завершённый удар (п. 20):
  нерезультативный удар без «отыгрыша» (два борта, или средняя линия и борт) — фол; в режиме полной траектории игра
  заранее предупреждает о фоле.
- **Московская (комбинированная) пирамида** — выбор в меню: биток только жёлтый; свояк — забивший снимает себе
  прицельный шар и бьёт с руки из дома (по шарам вне дома, они подсвечены; фол, если биток до выхода из дома задел шар в
  доме или не коснулся шара вне дома); временный дом, если все шары в доме; при фоле с битком в лузе соперник вводит
  биток с руки.
- **Сеть:** новый идентификатор KuNet `billiard2` и номер протокола — со старой версией не смешивается («Разные
  версии»); решения (штрафной шар, выбор после фола) уходят отдельными ходами, «Соперник выбирает…»; очередь отправки с
  повтором при сбое (раньше сбой сети мог «повесить» партию).
- **Проверено:** Node — 358 проверок на собранном коде (270 моделей разбоя: при силе 100 % правильных 97 %, при 35 % и
  ниже — фол; все фолы, штрафные шары, выборы, свояк, удар с руки, временный дом, п. 20; прогноз судьи совпал с ударом
  60/60); физика бит-в-бит совпадает с прежней версией; браузер — установка в 2D (43) и 3D (16), неправильный разбой и
